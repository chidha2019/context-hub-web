01

What we built

ContextHub takes an organization's scattered knowledge — GitHub, Jira, Slack — and turns it into one governed graph: who owns what, which policy applies, which ticket fixed which bug, who said what and where.

That graph is served two ways: through a chat-style Ask screen for people, and through MCP for AI agents like Claude Code. Both paths run through the exact same governance — access control, PII masking, injection screening, audit logging — so there's no back door.

The proof isn't a slide. It's asking the identical question three times, as three different people, and watching the answer — and the audit trail — visibly change.

Under the hood
  • Retrieval — keyword search + vector search + graph walk, fused and trust-weighted
  • Governance — per-persona access control, PII masking/redaction, prompt-injection screening
  • Synthesis — Claude (Haiku 4.5 via Bedrock) writes the answer, grounded only in what governance allowed through
  • Audit — every serve, from every entry point, logged to one table
  • Two front doors — the web UI and an MCP server, same governed core
02

How to run it

One command brings up the whole stack — synthetic data, backend, frontend.

1
From the repo root, run the demo command make demo
Generates the synthetic org, ingests it, starts both servers. Safe to re-run any time.
2
Open the app
localhost:5173 — the UI. localhost:8080 — the API, if you want to peek at it directly.
3
Pick a persona in the top bar, ask a question
Use the query on this page, or your own — it's a real pipeline, not a scripted demo.
4
For the MCP proof — reconnect Claude Code
The project already has an .mcp.json. Restart the Claude Code session (or run /mcp) so it picks up the new server before trying the MCP query.

05

The MCP query

Now ask the identical question a fourth way — not through the web UI at all, but through an external AI agent (Claude Code) connected over MCP.

Front door: the web UI

A person opens /ask, picks a persona in the TopBar, types a question.

Side door: MCP

An agent calls the graph.retrieve tool. Persona is fixed at connection time in .mcp.json — it can't be swapped mid-conversation.

Ask via MCP → a new row appears live in Governance with channel = mcp — same chunks, same masking, same audit, different door.

Sharing the codebase

What a colleague needs to do to run this themselves, from a fresh copy of the repo.

1
Copy or clone the repo
The whole project folder — frontend, server/, docs/.
2
Install the prerequisites
Python 3.11, uv (Python's package/venv manager), and Node.js.
3
Run the demo command from the repo rootmake demo
Everything else — venv, dependencies, synthetic data, both servers — is automatic.
4
Open the two URLs it prints and go
No manual setup steps beyond that.
⚡ About the AI answers

Live synthesis uses AWS Bedrock (Claude Haiku 4.5). Without Bedrock credentials configured, the app automatically falls back to a templated, still-governed answer built from the same retrieved context — the demo still works, the prose is just less fluent.

🔌 About the MCP step

Claude Code only reads .mcp.json on startup/reconnect. A colleague trying the MCP proof needs to restart their session (or run /mcp) after cloning, before it shows up as a connected tool.
